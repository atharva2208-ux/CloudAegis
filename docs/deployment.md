# Deployment

## Local: Docker Compose

```bash
git clone <repo> cloudaegis && cd cloudaegis
docker compose up --build
```

| URL | What |
|---|---|
| http://localhost:8080 | Web UI |
| http://localhost:8080/api/docs | Interactive API documentation |
| http://127.0.0.1:8000/health/ready | API readiness (bound to localhost only) |

Five services start in dependency order: `postgres` → `redis` → `backend` (waits for the database, runs `alembic upgrade head`, syncs the rule and compliance catalogs, creates the admin, seeds demo data) → `worker` (RQ scan worker) → `frontend` (nginx serving the SPA and proxying `/api`).

The first start takes about a minute while the demo history is generated by running the real scan pipeline seven times against the simulated provider. Sign in with the demo users shown on the login page. They all use the password `CloudAegis!Demo2026`.

Useful commands:

```bash
docker compose logs -f backend worker      # structured JSON logs with request and scan IDs
docker compose up --scale worker=3         # more scan throughput
docker compose run --rm backend migrate    # migrations only
docker compose exec backend python -m app.cli create-user alice@example.com "Alice Ng" SECURITY_ANALYST
docker compose down -v                     # stop and delete the database volume
```

## Local: without Docker

Requirements: Python 3.11+, Node 20+, PostgreSQL 14+, and optionally Redis.

```bash
createdb cloudaegis                        # or: CREATE DATABASE cloudaegis OWNER …;
export DATABASE_URL=postgresql+psycopg2://user:pass@localhost:5432/cloudaegis
./scripts/dev.sh setup                     # pip + npm install, migrate, seed demo data
./scripts/dev.sh api                       # http://localhost:8000 (scans run in-process)
./scripts/dev.sh web                       # http://localhost:5173 (Vite proxies /api)
```

## Production checklist

1. **Secrets.** Run `./scripts/generate-secrets.sh` and store `SECRET_KEY` and `CREDENTIAL_ENCRYPTION_KEY` in your secret manager. Rotating `CREDENTIAL_ENCRYPTION_KEY` makes stored credentials unreadable, so re-enter them after rotation.
2. **Environment.** Set `ENVIRONMENT=production`, `COOKIE_SECURE=true`, `DEMO_MODE=false`, `SEED_ADMIN_PASSWORD` (or create users with the CLI), and `LOG_JSON=true`.
3. **TLS.** Terminate HTTPS at a load balancer or ingress in front of the `frontend` container. Keep the API reachable only through nginx (same origin).
4. **Database.** Use managed PostgreSQL with encryption at rest, automated backups and TLS (`?sslmode=require` in `DATABASE_URL`).
5. **Redis.** Required for multiple API replicas, because it holds the shared rate-limit counters and the scan queue.
6. **Scale.** API replicas are stateless. Add `worker` replicas for scan throughput, and set `SCAN_TIMEOUT_SECONDS` for very large accounts.
7. **Observability.** Ship container stdout (JSON lines with `request_id`, `scan_id` and user) to your log platform. Point liveness probes at `/health/live` and readiness at `/health/ready`. Unhandled errors are logged with full stack traces under `unhandled_exception`.

## AWS setup

### 1. CloudAegis' own identity

The platform needs an identity that can call `sts:AssumeRole`. Prefer an **EC2 instance profile, ECS task role or EKS IRSA** over static keys. Set `PLATFORM_AWS_PRINCIPAL_ARN` to that role's ARN, and the onboarding page will put it into the trust policy for you.

Minimal policy for the platform role:

```json
{
  "Version": "2012-10-17",
  "Statement": [{ "Effect": "Allow", "Action": "sts:AssumeRole", "Resource": "arn:aws:iam::*:role/CloudAegisAudit" }]
}
```

### 2. Audit role in each assessed account

Use **Accounts → Add account**. The wizard shows a CloudFormation template, a trust policy and a least-privilege permissions policy, with your external ID filled in. You can also deploy with the CLI:

```bash
aws cloudformation deploy \
  --stack-name cloudaegis-audit-role \
  --template-file cloudaegis-audit-role.yaml \
  --capabilities CAPABILITY_NAMED_IAM
```

The role:

- trusts only the CloudAegis principal, and only with the matching `sts:ExternalId`;
- grants only `Describe*`, `Get*` and `List*` actions (or AWS's `SecurityAudit` managed policy);
- can be revoked at any time by deleting the stack, which stops all CloudAegis access immediately.

Paste the role ARN into the wizard. CloudAegis verifies the role with `sts:GetCallerIdentity`, discovers the enabled regions, and runs the first scan.

### 3. Temporary credentials (optional)

For a one-off assessment you can paste STS session credentials (`aws sts get-session-token` or `assume-role` output). They are encrypted at rest and expire on their own. Long-lived `AKIA…` keys are rejected.

## Upgrades

```bash
docker compose pull && docker compose up -d --build   # the backend applies migrations on start
```

Migrations are forward-only Alembic revisions. Back up the database before upgrading.
